# Brief: Private Data Union (G4) — swarm-rag-engineer

Task (one sentence): Build the Private Data Union module (package `com.swarmos.app.pdu`): each phone indexes its own photos and documents locally, a question is sent as text to every phone, each returns only top snippets, and the asking phone merges them, writes an answer with its local model and cites the phone and file behind every fact.

Read first: CLAUDE.md, docs/CONTRACTS.md (all, note 9.4 and 9.6), .claude/agents/swarm-rag-engineer.md, plans/briefs/_common.md, docs/PRD.md section 5.4, and from docs/research/04-private-data-union-rag.md only the federated protocol, ingestion and latency-budget sections (grep the headings). Then the scaffold code: app/app/src/main/java/com/swarmos/app/AppGraph.kt, core/*, llm/LlmClient.kt, llm/FakeLlmClient.kt, link/NodeClient.kt, link/NodeServer.kt, pdu/*.

Build flags: `-PidSuffix=.pdu -PportOffset=30`.

You own: app/app/src/main/java/com/swarmos/app/pdu/** , app/app/src/test/java/com/swarmos/app/pdu/** , scripts/make-demo-corpus.py , docs/demo-corpus/** .

Peers: read online peers from AppGraph.registry. The discovery module is being built by another worker at the same time, so add a debug way to register peers by IP in your module (a signed POST /v1/pdu/debug/peers {ips: [...]} that calls GET /v1/hello on each and adds them to the registry).

Build:
1. Store (CONTRACTS 9.4): one SQLite DB in filesDir through the androidx.sqlite bundled driver: table chunks(id, docId, uri, title, kind, dateMs, folder, isPrivate, text, emb BLOB) plus an FTS5 virtual table over text and title. Embeddings are 256-dim float32 from AppGraph.embedder.embed (already normalised); cosine by brute force in Kotlin over an in-memory float matrix loaded at start; BM25 through FTS5; fuse with reciprocal rank fusion (k = 60).
2. Ingestion, all on-device:
   - Photos: MediaStore images (READ_MEDIA_IMAGES), ML Kit text recognition, title = file name, date taken. Skip images with fewer than 20 characters of text.
   - Documents: a folder chosen with the Storage Access Framework (persisted permission): .txt and .md read directly; text PDFs through pdfbox-android; PDFs with no text layer through PdfRenderer then ML Kit OCR per page; .docx by unzipping word/document.xml and stripping tags.
   - Camera: "Scan document" captures a photo with CameraX, OCRs it and indexes it (a scored "creative phone use" item).
   - Chunking: about 250 tokens (approximate as 1000 characters) with 15 % overlap, each chunk prefixed with the title. Indexing runs in the SwarmService scope with a progress StateFlow, is resumable (skip documents already indexed by uri + lastModified), and never uploads anything.
   - Share policy: a per-folder "private" toggle; private chunks are searchable by the owner phone only and are never returned to peers. Any folder named Private is private by default.
3. Federated query: the asking phone sends signed POST /v1/pdu/query {qid, text, k: 5, deadlineMs: 1500} to every online peer and runs the same search locally. Each phone embeds the query text itself, searches, applies the share policy, and returns [{title, uriHash, kind, dateMs, snippet (at most 400 chars), score, rank}] plus {indexedChunks, tookMs, withheldPrivate}. Never return embeddings, full files, file paths beyond the title, or EXIF. Late or absent peers are listed as unreachable and the answer is flagged "possibly incomplete". Nothing received from peers is persisted except one audit-log line {qid, peer, n, bytes}.
4. Merge and answer: RRF across devices on per-device ranks, dedupe near-identical snippets, take the top 6, prompt AppGraph.llm (streamed) with numbered sources like "[n] Phone B · IMG_2231.jpg · 2025-03-14: snippet" and instruct it to answer in at most 80 words citing [n]; if nothing relevant is found, say so. Show snippet cards immediately (before the model writes), then the streamed answer with tappable citations. Tapping a citation of a local file opens it (ACTION_VIEW); for a peer's file send POST /v1/pdu/open {uriHash} so it opens on the owning phone's screen.
5. Screen: index status (documents, chunks, last run), buttons Index photos / Pick folder / Scan document, private-folder toggles, query box, results as described, a timing strip (embed ms, local search ms, per-peer round trip ms, time to first token, total), and a per-query audit view "what left this phone / what each phone returned".
6. scripts/make-demo-corpus.py (PC side, Python 3.12; `pip install pillow reportlab` is allowed): generates clearly synthetic demo files into docs/demo-corpus/A, B, C: for B a photographed-looking receipt image "Laptop warranty bill" (store name, model, serial, purchase date, warranty period, amount in INR); for A a text PDF "Laptop extended warranty certificate" with different details (expiry date, policy number); for C an unrelated set (electricity bill image, a Hindi note image, meeting notes .txt); and on B one file in a folder named Private (salary slip) to demonstrate withholding. 10-15 files per phone including distractors. Push them with adb to /sdcard/Pictures/SwarmDemo and /sdcard/Documents/SwarmDemo on each phone (creating these two folders on the phones is allowed) and print the adb commands used.

Verify:
- JVM unit tests: chunker, RRF merge and dedupe, share-policy filter (a private chunk never appears in a peer response), cosine top-k against a tiny fixture.
- On the phones with the fake embedder and model (the real runtime is being built by another worker; FakeLlmClient.embed is a deterministic hash embedding, so BM25 carries retrieval for now): install your variant on A, B, C; grant READ_MEDIA_IMAGES over adb; index the demo corpus on each through a signed POST /v1/pdu/index route (nobody can tap the SAF picker, so for the demo folder also support scanning /sdcard/Documents/SwarmDemo directly when all-files access was granted with `adb shell appops set <pkg> MANAGE_EXTERNAL_STORAGE allow`; that appops grant on your own package is allowed, and say in the report which path you used); run "Where is the warranty bill for my laptop?" from A through a signed POST /v1/pdu/ask route that runs the full federated flow and returns sources and timings: the receipt on B and the certificate on A must both be in the top sources with the correct phone attribution; the salary slip on B must be reported only as withheldPrivate. Record OCR quality problems honestly.
- Timings from the phones for: OCR per image, index total, local search ms, peer round trip ms. Put them in the report (the orchestrator writes the benchmark file once the real models are in).
