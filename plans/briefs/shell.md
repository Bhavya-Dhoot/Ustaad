# Brief: App shell (first-run setup, settings, status strip fixes) — swarm-android-builder

Task (one sentence): Build the app shell screens of Ustaad with the Whiteboard UI kit: the first-run setup, the settings sheet with the audit-log check, and the missing kit helpers, and fix the status strip so it always shows real link data.

Read first: CLAUDE.md, docs/CONTRACTS.md (sections 3, 8, 9, 10), plans/briefs/_common.md, docs/design/DESIGN.md (binding), ui-kit/README.md, then look at `ui-kit/screens/first_run_setup/screen.png` and `ui-kit/screens/settings_sheet/screen.png` with the Read tool and read their code.html for spacing. Then the code: app/app/src/main/java/com/swarmos/app/MainActivity.kt, AppGraph.kt, ui/* (the kit: use it), core/HealthMonitor.kt, core/AuditLog.kt, core/SwarmPrefs.kt, core/SwarmService.kt.

Build flags: `-PidSuffix=.shell -PportOffset=60`.

You own: a new package app/app/src/main/java/com/swarmos/app/shell/** (setup and settings screens), additions to ui/** (new helpers only; do not change existing composable signatures), core/HealthMonitor.kt, core/SwarmPrefs.kt, and the parts of MainActivity.kt that show setup and settings (list your exact edits; other workers also touch MainActivity, so keep edits small and local).

Build:
1. First-run setup (matches first_run_setup): title "Three things before we start", three rows, each with a line icon, a one-line reason and a button, turning into a check mark when done: "Allow nearby devices" (requests NEARBY_WIFI_DEVICES, ACCESS_FINE_LOCATION, BLUETOOTH_SCAN, BLUETOOTH_ADVERTISE, BLUETOOTH_CONNECT), "Allow notifications" (POST_NOTIFICATIONS), "Turn off battery limits for Ustaad" (ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS for this package; state read from PowerManager.isIgnoringBatteryOptimizations). A fourth, optional row appears only on vivo/iQOO devices: "Allow background start" opening the app's system settings page, with one handwritten note explaining that the phone otherwise stops the swarm when the screen is off. Primary button "Continue" is enabled when the first three are done; "Skip for now" is a secondary text action. Shown on launch until completed or skipped (stored in SwarmPrefs); `--ez setupDone true` on the launch intent marks it done so phones can be driven over adb. Camera and photo permissions are requested later by the screens that need them, not here.
2. Settings sheet (matches settings_sheet), opened from the status strip instead of the plain name dialog: "Phone name" input; identity picker with the three phone tokens A, B, C that sets the name to "Phone A/B/C" (colour follows the name); "Pairing secret" row with "Reset" (new random secret, with a confirm step that says peers must pair again); switch "Remove animations" (an in-app preference that `rememberAnimationsEnabled()` must honour in addition to the system setting); "Audit log" row showing the entry count and a "Verify" action that runs AuditLog.verify() and shows the outline stamp "CHAIN OK" or the hatched stamp "CHAIN BROKEN" with the first bad entry index; app version row "Ustaad <versionName>". No invented rows.
3. Kit helpers the screen workers asked for: `EmptyHint(text, modifier)` (one handwritten line with a hand-drawn arrow pointing down-right), a screen-change transition helper (180 ms fade and 8 dp rise, once, disabled when animations are removed) applied where MainActivity switches tabs, and `ErrorNote(text)` (ink text with a hatched left bar).
4. Status strip correctness: on phone C the strip showed "no wifi" while Wi-Fi was connected (HealthMonitor.linkSpeedMbps was null). Make HealthMonitor read link standard, PHY speed and frequency reliably on Android 16 without needing location permission (ConnectivityManager NetworkCapabilities transportInfo as WifiInfo, falling back to WifiManager.connectionInfo), and show "no link" only when there is none. Thermal status shown as a word (Cool, Warm, Hot, Severe). When thermal status is 3 or more the strip shows a hatched "HOT" stamp instead of the internet stamp.
5. The word "Ustaad" appears as a small Bricolage Grotesque wordmark at the top of the setup screen and in the settings sheet only; the status strip stays as designed.

Verify:
- JVM unit tests for the setup-state logic (which rows are done, when Continue enables) and for the thermal word mapping.
- Install your variant on phone B. Fresh install shows setup; grant the permissions over adb (`pm grant`), re-open: rows show check marks; battery row: report what the system dialog and the vivo path look like (screenshot), do not change the setting; `--ez setupDone true` skips setup. Open settings: rename, switch identity, verify the audit chain (CHAIN OK), toggle Remove animations and confirm the stamp no longer animates. Screenshots to docs/design/shots/shell-setup.png and shell-settings.png; compare with the Stitch PNGs and list remaining differences.
- Status strip on A, B and C shows the real link (for example "11ac 433 Mbps") on all three; report the values.
